# Rokid 안경 앱 개발 노트

rokid-conversate 를 만들면서 알게 된 것 중, 다른 Rokid 안경 앱에서도 다시 쓸 만한 사실과 방법을 모았다.
작성: 2026-11-06. 판정 표기는 `docs/00-summary.md` 와 같다.
- **실기**: 안경에서 직접 확인함. 사용자 보고나 서버 로그로 확인한 것 포함.
- **서버**: 클라우드·실서버(Railway)에서 직접 돌려 확인함.
- **문서**: 문서나 소스만 읽음.
- **미확인**: 위 어디에도 해당하지 않음.

---

## 1. 기본 구조: iPhone 사용자는 폰 앱 없이

| 내용 | 판정 |
|---|---|
| 폰 쪽 연동 SDK(CXR-M)는 안드로이드 전용이라 iPhone 에서는 못 쓴다. **안경 단독 APK → 폰 핫스팟 → 서버 WebSocket** 구조로 간다. | 문서 |
| 안경 앱이 서버에 WebSocket(`wss://…/ws`, Bearer 토큰)으로 직접 붙고, 소리는 16 kHz 모노 PCM 바이너리로, 결과는 JSON 텍스트로 주고받으면 충분하다. | 실기 |
| 서버 주소와 토큰은 빌드할 때 APK 에 넣는다(`BuildConfig`). 안경에 키보드가 없기 때문이다. 바꿀 때는 `am start … --es config 'CONVERSATE:url=…;token=…'` 로 넣고 앱이 저장해 둔다. | 서버 (adb 명령은 미확인) |
| **iPhone 핫스팟은 연결된 기기가 없으면 잠든다.** 안경이 못 붙으면 iPhone 에서 설정 → 개인용 핫스팟 화면을 한 번 연다. | 문서 |
| 애플의 인스턴트 핫스팟(꺼진 핫스팟을 Wi-Fi 목록에서 골라 켜기)은 애플 기기끼리만 된다. 대신 **iPhone 단축어 자동화**: 단축어 → 자동화 → 블루투스 → Rokid 안경 "연결될 때" → 즉시 실행 → 동작 "개인용 핫스팟 켜기". 안경이 블루투스로 붙으면 핫스팟이 켜지고, 앱이 Wi-Fi 를 켜면 저장된 핫스팟에 자동으로 붙는다. 손대지 않고 연결된다. | 실기 (2026-11-11) |

## 2. 화면

| 내용 | 판정 |
|---|---|
| 480x640 녹색 단색 표시. 네비 앱과 같이 **480x282 논리 단위를 비율 유지해 화면 아래 가운데**에 그리고, 여백 18, 색 `#00ff66`(강조) / `#4da86c`(보조)를 쓴다. | 실기 |
| 검은 픽셀은 빛이 안 나온다. **UI 는 검은 바탕에 얇은 초록 테두리와 어두운 글씨**로 만든다. 밝은 면이 많으면 앞이 안 보인다. | 실기 |
| **시스템 설정 화면(Wi-Fi 설정 등)은 밝고 커서 앞을 가린다.** 앱이 저절로 열지 말고, 상태는 자체 HUD 카드로 보여 준다. 시스템 화면은 사용자가 탭했을 때만 연다. | 실기 |
| 녹색 단색이라 사진은 흑백으로 받아 `ColorMatrixColorFilter` 로 밝기를 초록 채널에 넣어 그린다. 56px 는 너무 작아서 못 알아본다. 84px 이상으로, 카드 밖에 따로 그린다. | 실기 |
| 실기 없이 화면을 볼 때는 **Paparazzi** 로 480x282 dp 스냅샷을 만든다(`./gradlew :app:recordPaparazziDebug`). 화면을 바꾸면 스냅샷도 같이 커밋한다. | 서버 |
| 음량 막대 같은 것 때문에 100 ms 마다 `invalidate()` 하지 않는다. 표시할 값(칸 수)이 바뀔 때만 다시 그린다(배터리). | 서버 |

## 3. 입력 (터치패드, R08 링)

| 내용 | 판정 |
|---|---|
| 터치패드: 탭 = `ENTER`, 앞뒤로 쓸기 = `DPAD_LEFT/RIGHT` 또는 Rokid 키 `183/184`, 두 번 탭 = `202` 또는 `BACK`. 길게 누르기와 다리 버튼은 시스템이 가져간다. | 문서 (다른 프로젝트 RokidPipe 에서 실기 확인) |
| 쓸기는 한 번에 여러 키가 오기도 하니, 방향 키는 짧게 디바운스하고 `repeatCount > 0` 은 무시한다. | 문서 |
| **R08 링**: R08 Access Bridge 앱이 접근성으로 포커스된 노드에 스크롤 앞/뒤·클릭을 보낸다. 화면 전체를 그리는 View 하나를 접근성 노드로 만들고 `ACTION_SCROLL_FORWARD/BACKWARD`, `ACTION_CLICK` 을 받으면 된다. 브리지 없이 Stable 모드면 미디어 키(`MEDIA_NEXT/PREVIOUS/PLAY_PAUSE`)가 온다. | 문서 (네비 앱 방식, 이 앱에서는 미확인) |

## 4. 마이크

| 내용 | 판정 |
|---|---|
| `AudioSource.VOICE_RECOGNITION` 은 **전부 0** 이다. 기본 비서가 쓰고 있어서다. | 실기 |
| `AudioSource.MIC` + 채널 마스크 **`0x6000FC`** 로 열면 8채널이 섞여서(interleaved) 들어온다. 0·1 = 처리된 채널(에코 제거·빔포밍), 2~5 = 원래 마이크 캡슐 4개, 6·7 = 에코 참조. | 실기 |
| 처리된 채널은 **착용자 목소리**가 잡음 대비 약 100배로 깨끗하지만, **앞사람 목소리는 약해진다**. 원래 캡슐 평균은 약 7배다. | 실기 |
| 그래서 100 ms 마다 `처리 채널 ×2` 와 `캡슐 평균 ×4` 중 큰 쪽을 고르고, 1.25배 이상 차이 날 때만 바꾼다(히스테리시스). 둘 다 잘 잡혔다. | 실기 |
| 소스를 열었는데 처음 1.5초가 전부 0이면 다음 소스로 넘어가는 구조로 둔다. 기기와 펌웨어마다 다르다. | 실기 |
| 앱이 `onPause` 되면 마이크를 놓아야 한다. 그래야 다른 앱과 비서가 마이크를 쓴다. | 문서 |

## 5. Wi-Fi 자동으로 켜기 (중요)

안경은 배터리 때문에 Wi-Fi 를 꺼 두는 일이 많아서, 앱이 직접 켜야 한다.

| 내용 | 판정 |
|---|---|
| `WifiManager.setWifiEnabled(true)` 는 **targetSdk 29 이상 앱에서는 아무 일도 안 하고 false** 를 돌려준다. | 실기 |
| `Settings.Global.WIFI_ON` 쓰기는 `WRITE_SECURE_SETTINGS` 가 필요하다. 이 권한은 adb 로만 줄 수 있다(`pm grant`). 컴퓨터와 케이블이 있어야 해서 일반 사용자에게는 현실적이지 않다. | 실기 |
| 숨은 API(`IWifiManager` 리플렉션)도 targetSdk 28 을 넘으면 막힌다. | 미확인 |
| **해결: targetSdk 28 로 만든 작은 "도우미 앱"을 따로 설치한다.** 안드로이드는 targetSdk 28 이하 앱에는 아직 Wi-Fi 켜기를 허용한다. 본앱을 28로 낮추면 무확인 OTA(아래 6)가 막혀서 분리했다. 구현은 `glasses/wifihelper` 에 있다. | 실기 |
| 도우미는 한 번도 실행된 적이 없는 앱이라, **broadcast 를 보내도 받지 못했다**(`FLAG_INCLUDE_STOPPED_PACKAGES` 를 붙여도). `Theme.NoDisplay` 액티비티를 `startActivity` 로 띄우면 바로 켜졌다. 그래서 액티비티를 먼저 시도한다. | 실기 |
| 액티비티를 띄우면 본앱이 잠깐 `onPause`/`onResume` 된다. Wi-Fi 가 꺼져 있을 때만, 10초 간격 이상으로 띄운다. | 실기 |
| 실기에서 로그를 볼 수 없으므로 **실패 이유를 화면에 보여 주게** 만든다. 도우미가 결과(거부 / 오류 / 비행기 모드 / 받아들였는데 아직 꺼짐)를 본앱에 broadcast 하고, 본앱이 HUD 카드에 표시한다. 이 방법으로 원인을 찾았다. | 실기 |
| 어느 네트워크에 붙을지는 시스템에 맡긴다. Android 12 에서 앱이 네트워크를 직접 고르려면 시스템 확인 창이 뜬다. 핫스팟은 한 번 연결해 두면 자동으로 다시 붙는다. | 문서 |
| 다른 앱 패키지를 확인하거나 띄우려면 매니페스트에 `<queries><package …/></queries>` 를 넣는다. | 서버 |

## 6. 설치와 무확인 자동 업데이트(OTA)

| 내용 | 판정 |
|---|---|
| 업데이트를 `PackageInstaller` 세션 + `setRequireUserAction(USER_ACTION_NOT_REQUIRED)` 로 설치하면 안경에서 아무것도 누르지 않고 업데이트된다. 이 무확인 설치는 **설치하는 앱의 targetSdk 가 충분히 높아야** 한다(Android 12 는 29 이상). | 실기 |
| `MY_PACKAGE_REPLACED` 리시버로 업데이트 뒤 앱을 다시 띄운다. 업데이트 확인은 앱을 켤 때 한 번만 한다. | 실기 |
| **릴리스 서명 키는 고정**한다. 잃어버리면 OTA 가 불가능해져서 지우고 다시 설치해야 한다. 키와 비밀번호는 저장소 밖에 둔다. | 실기 |
| **릴리스 빌드에 서버 주소와 토큰이 빠지면 앱이 서버에 못 붙고, OTA 로도 복구가 안 된다.** 0.1.14 에서 실제로 겪었다. 릴리스 스크립트가 주소·토큰 없이는 빌드를 거부하게 하고, 빌드 후 `unzip -p app.apk 'classes*.dex' \| strings \| grep 서버주소` 로 확인한다. | 실기 |
| OTA 서버는 `/app/latest`(버전 JSON)와 `/app/download`(APK)만 있으면 된다. 업로드는 별도 토큰으로 막는다. | 서버 |

## 7. 배터리

| 내용 | 판정 |
|---|---|
| 조용할 때까지 PCM(초당 32 KB)을 계속 보내면 Wi-Fi 가 쉬지 못한다. **안경에서 소리 크기로 거르고(SpeechGate) 말소리 근처만 보낸다.** 기준은 소음 바닥의 3배가 0.2초 이어지면 열고, 직전 0.8초부터 보내고, 조용해진 뒤 1.5초 더 보낸다. 서버 쪽 끝 판정(0.7초 조용함)이 동작하려면 이 1.5초가 필요하다. | 서버 (배터리 효과는 미확인) |
| 2배 / 한 번만 넘으면 열리게 했을 때는 부스럭·탁 소리에도 계속 열렸다. | 실기 |
| 화면 꺼짐(자막 숨김)을 서버의 "말소리 있음"(VAD) 신호로 미루면, 작은 잡음에도 영영 안 꺼진다. **실제 자막 글자가 올 때만** 타이머를 연장한다. | 실기 |
| 말하는 동안의 소리를 **Opus 32 kbps** 로 보낸다 (안드로이드 내장 인코더 `MediaCodec` "audio/opus", API 29+). PCM 의 8분의 1. 서버는 PyAV(faster-whisper 의존성이라 이미 있음)로 풀어서 PCM 으로 쓴다. 왕복해도 받아쓰기 결과가 같았다. 인코더가 없거나 실패하면 PCM 으로 돌아간다. | 서버 (안경 인코더는 미확인) |
| **3분 동안 소리가 없으면 서버 연결을 끊고**, 마이크는 안경 안에서만 듣는다. 소리가 나면 다시 연결하고, 그동안의 소리(최대 6초)를 이어서 보낸다. | 미확인 |
| 아무것도 안 띄울 때 창 밝기를 최소(`screenBrightness`)로. Rokid 화면이 따르는지는 미확인. 앱 오른쪽 아래에 모드 시작 뒤 시간당 배터리 소모(%/h)를 띄우고 서버 로그에도 남겨, 바꾼 효과를 숫자로 본다. | 미확인 |
| 소리가 안 오면 서버의 수신 루프도 안 돈다. 돈이 드는 세션(실시간 번역 등)은 수신 루프가 아니라 별도 타이머로 닫는다. | 서버 |

## 8. 서버 쪽 음성 처리

| 내용 | 판정 |
|---|---|
| 말소리 구간 판정은 에너지 기준만으로는 놓친다. **WebRTC VAD mode 1** 이 적당하다. mode 2 는 작은 첫 단어("안녕하세요")를 잘랐다. 여기에 "소음 바닥의 2배 이상" 조건을 더하면 잡음을 거르면서 실제 말소리는 그대로 잡힌다. | 서버 |
| 로컬 Whisper `small`(CPU)은 한국어가 약하다("분기"→"붕기"). **미확정 자막은 로컬 Whisper, 확정 자막은 `gpt-transcribe`**(분당 $0.0045)로 나누는 하이브리드가 좋다. 언어 후보(`ko,en,ja,zh`)를 주면 외국어가 한국어로 억지로 받아써지지 않는다. | 서버 |
| Whisper 를 `language="ko"` 로 고정하면 영어를 7~13초 동안 지어낸 한글로 받아쓴다. **첫 미확정 자막(0.8초)에서 언어를 감지**하고 그 발화 동안 재사용한다. | 서버 |
| 언어 감지는 별도 **Whisper `base`** 로 하면 0.3초에 정확하다. `tiny` 는 한국어를 중국어로 봤고, `small` 자체 감지는 약 1.5초 걸렸다. "다른 언어가 0.5 이상이고 ko 가 0.1 미만일 때만 외국어"로 판정한다. | 서버 |
| Whisper 는 잡음에서 "시청해 주셔서 감사합니다", "구독과 좋아요", "음..." 같은 문구를 지어낸다. 이런 문장 하나만 나오면 버린다. | 서버 |
| 미확정 자막과 확정 자막은 따로 돌린다. 한 루프에서 처리하면 서로 막아서 자막이 멈췄다가 한꺼번에 나온다. | 서버 |

## 9. 실시간 번역 (`gpt-realtime-translate`)

| 내용 | 판정 |
|---|---|
| `wss://api.openai.com/v1/realtime/translations?model=gpt-realtime-translate`, `session.update` 로 출력 언어 지정, 입력은 24 kHz PCM16 base64(`session.input_audio_buffer.append`). 세션이 열려 있는 동안 분당 $0.034 다. | 서버 |
| 번역(`session.output_transcript.delta`)은 한두 글자씩 바로 온다. **원문(`input_transcript`)은 약 30초 늦게 한꺼번에** 와서 쓸 수 없다. 원문은 우리 STT 로 만들고 번역만 같은 자막 id 에 붙인다. | 서버 |
| 번역 조각에 띄어쓰기가 빠질 때가 있다. 구절 안은 띄어 오지만 구절 사이는 붙어 온다("있어요여기"). 문장부호 뒤와, 쉰 뒤 어미(요·다·고…)가 오면 띄운다. | 서버 |
| 외국어가 감지되는 순간 세션을 열고, 그때까지의 소리(최대 8초)를 다시 보내면 첫 문장부터 번역된다. 번역이 원문 받아쓰기보다 먼저 오면 원문 없이 먼저 띄운다. | 서버 |
| 문장이 끝난 뒤 문장 번역으로 무조건 갈아끼우면 글이 튄다. 그렇다고 실시간 번역만 쓰면 줄이 밀린다. **문장 번역과 뜻이 비슷하면 두고, 다르면 바꾼다.** | 실기 |
| **번역 조각은 도착 순서로 붙이면 한 줄씩 밀린다**(실사용 기록에서 다수 확인). 조각의 `elapsed_ms` 가 번역 세션에 넣은 소리의 시각을 따라가므로, 서버가 각 문장이 세션 소리 몇 ms 에서 끝났는지 기록해 두고 그 시각으로 붙인다. | 서버 |
| 짧은 한국어 말("아하", "오")이 영어·일본어로 받아써져 번역이 붙는다. 받아쓰기가 외국어라고 하면 소리로 언어를 다시 판정하고(Whisper base), 한국어면 한국어로 다시 받아쓴다. | 서버 |
| 일본어는 동사가 끝에 와서 번역이 영어보다 늦다(모델 특성). | 서버 |

## 10. AI 비용과 속도 (OpenAI)

| 내용 | 판정 |
|---|---|
| 비용의 절반 이상이 **웹 검색**이었다. 검색한 답 하나가 검색 결과 약 9,500 토큰을 읽었다. **판단 단계가 "검색 필요?"까지 정하게** 하니 일반 지식 답은 약 700 토큰, 1.7초가 됐다. | 서버 |
| 환율·단위 환산은 LLM 없이 정규식과 무료 환율 API(open.er-api.com, 1시간 캐시)로 바로 낸다. 8~9초 걸리던 카드가 즉시 뜬다. | 서버 |
| 2단계 구조가 좋다. 싸고 빠른 판단(띄울지, 무엇을, 검색할지 JSON)을 하고, 필요할 때만 답을 낸다. 판단 결과의 인용문이 방금 들은 말에 실제로 있는지 검사하면 엉뚱한 카드가 준다. | 서버 |
| 결제 등급 1(분당 1만 토큰)에서는 검색 한 번(약 9천 토큰)으로 한도를 넘어 429 가 난다. $5 결제로 등급이 올라가면 분당 100만 토큰이 된다. 429 에는 재시도하지 말고 잠시 쉰다. | 서버 |

## 11. 개발 방식

| 내용 | 판정 |
|---|---|
| 클라우드에서는 실기를 못 돌린다. 문서에 실기 확인 여부를 반드시 적는다. | - |
| 실기 대신 **녹음 파일을 실시간 속도로 서버 WebSocket 에 흘려** 확인한다. 테스트 음성은 TTS 로 만든다(gTTS, 구글 번역 TTS). | 서버 |
| 실서버 로그(Railway)에 각 단계 시간과 토큰 수를 남기면 느린 곳과 비싼 곳을 바로 찾는다. 예: `stt partial #3: 1.6s audio in 1.57s`, `assist answer: … tokens in/out`. | 서버 |
| 실기 문제는 로그 대신 **화면에 원인을 표시**하게 만들어 사용자 보고로 푼다(5의 Wi-Fi 사례). | 실기 |
